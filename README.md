# 多设备事件对时工具

现场排障用的网页小工具：把多台设备导出的 JSONL 事件流粘贴进来，为每台设备配置若干
“本地时间 → 基准时间”同步锚点，系统按相邻锚点做**分段线性校时**，把所有设备的事件
合并到一条统一时间线上，方便跨设备还原故障发生时序。

## 功能

- 多设备管理：任意添加/删除设备，每台设备独立粘贴 JSONL 事件流
- 同步锚点：每行一条 `本地时间, 基准时间[, ±误差毫秒]`（支持 ISO 8601 字符串或 epoch 毫秒，第三列可选）
- 分段线性校时：相邻锚点之间线性插值；单锚点退化为纯平移
- **时间不确定性**：锚点可填写 ±误差毫秒，校时按区间算术沿当前分段插值/外推，
  给出每条事件校正时间的最早/最晚边界；统一时间线仍按中心值排序
- **顺序不确定标记**：相邻事件的校正区间相交（含端点相切）时，这一对事件双方都标记
  “顺序不确定”，工具栏可一键只看此类事件
- 锚点校验：**本地时间或基准时间倒序/重复、误差为负数或非数字都会被拒绝**，报错定位到锚点行
- 外推标记：落在锚点区间之外的事件按最近一段斜率外推，并标记“区间前 / 区间后”
- 统一时间线：按校正后中心值排序合并，可同时查看原始时间、校正时间与校正区间，可隐藏外推事件
- 导出：一键下载合并后的 JSONL（含原始时间、校正时间、校正区间、顺序不确定标记与原始事件）
- 时间字段：默认自动探测 `ts` / `time` / `timestamp`，也可逐设备指定字段名

## 快速开始（Docker，单条命令）

```bash
docker compose up --build
```

启动后访问：**http://localhost:8080**（端口 `8080`）。

## 本地开发（Node.js ≥ 18）

```bash
npm install
npm start        # 同样监听 http://localhost:8080
npm test         # 运行核心校时逻辑单元测试
```

端口可通过环境变量覆盖：`PORT=9000 npm start`（Compose 中同步修改 `ports` 映射）。

## 使用说明

1. 点击 **+ 添加设备**，填写设备名称。
2. 在“同步锚点”框中每行填写一条锚点：`本地时间, 基准时间[, ±误差毫秒]`
   （也支持 `->` 或 Tab 分隔，`#` 开头为注释行）。基准时间通常取 NTP 服务器的
   标准时钟或抓包时间。锚点必须按本地时间和基准时间双双递增，否则提交时会被拒绝。
   - 第三列误差可选，单位毫秒，**未填写按 0 处理**；接受 `50`、`±50`、`50ms` 等写法。
   - 该误差表示锚点基准时钟的不确定范围（如 NTP 同步抖动、人工对时误差）。
   - 误差为负数或非数字时会被拒绝，错误信息定位到具体锚点行。
3. 在“事件流”框中粘贴该设备的 JSONL 日志（每行一个 JSON 对象）。
4. 点击 **校时并合并**，下方出现统一时间线：
   - 表格同时展示原始（设备本地）时间、校正（基准）时间与“校正区间”（最早 → 最晚，附 ±毫秒）；
   - “外推”列标出锚点区间外的事件（黄色行），可用复选框隐藏；
   - “顺序”列标出与相邻事件校正区间相交的事件（红色行），勾选 **只看顺序不确定**
     可一键过滤出这类事件（汇总额外统计其数量）；
   - “紧凑模式”隐藏原始时间列，只看校正后时序。
5. 点击 **导出合并 JSONL** 下载结果，每行格式：

```json
{
  "correctedTime": "2026-09-21T10:05:02.250Z",
  "correctedTimeMs": 1789985102250,
  "earliestTime": "2026-09-21T10:05:02.100Z",
  "earliestTimeMs": 1789985102100,
  "latestTime": "2026-09-21T10:05:02.400Z",
  "latestTimeMs": 1789985102400,
  "uncertaintyMs": 150,
  "orderUncertain": false,
  "device": "switch-A",
  "rawTime": "2026-09-21T10:05:00.000Z",
  "rawTimeMs": 1789985100000,
  "extrapolated": null,
  "event": { "ts": "2026-09-21T10:05:00.000Z", "msg": "crc rising" }
}
```

页面上的 **载入示例** 按钮可一键填充两台设备的演示数据。

## 校时算法

设设备锚点为 `(L₁,R₁,u₁)…(Lₙ,Rₙ,uₙ)`（本地→基准，`u` 为 ±误差毫秒，均已校验严格递增）。
对事件本地时间 `t`，先确定中心值校正系数 `r`：

- `Lᵢ ≤ t ≤ Lᵢ₊₁`：`r = (t − Lᵢ) / (Lᵢ₊₁ − Lᵢ)`（分段线性内插，`0 ≤ r ≤ 1`）
- `t < L₁`：取首段，`r < 0`，标记 `before`
- `t > Lₙ`：取末段，`r > 1`，标记 `after`
- `n = 1`：纯平移 `R = R₁ + (t − L₁)`，误差恒为 `u₁`，除锚点本身外均标记为外推

中心校正值与区间边界（区间算术，仿射组合取系数绝对值）：

```
R     = (1 − r)·Rᵢ + r·Rᵢ₊₁
半宽  = |1 − r|·uᵢ + |r|·uᵢ₊₁
最早  = R − 半宽
最晚  = R + 半宽
```

内插时系数均非负，误差在两锚点之间线性过渡；外推时系数出现负号，误差会被放大，
这符合“离锚点越远越不可信”的直觉。

**顺序判定**：所有设备的事件仍按中心校正值排序；逐条比较相邻事件的区间，
若上一条的 `latest ≥` 下一条的 `earliest`（端点相切也算），则两者先后无法确定，
双方均置 `orderUncertain: true`。

```

```

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/sync` | 提交设备列表（锚点 + JSONL 原文），返回合并时间线与导出 JSONL |
| POST | `/api/parse-anchors` | 解析锚点文本（前端辅助，支持可选第三列 ±误差毫秒，坏值定位到行） |
| GET | `/api/health` | 健康检查 |

`POST /api/sync` 请求体示例：

```json
{
  "devices": [
    {
      "name": "switch-A",
      "timeField": "ts",
      "anchors": [
        { "local": "2026-09-21T10:00:00Z", "ref": "2026-09-21T10:00:02.5Z", "uncertaintyMs": 50 },
        { "local": "2026-09-21T10:10:00Z", "ref": "2026-09-21T10:10:02Z" }
      ],
      "eventsText": "{\"ts\":\"2026-09-21T10:05:00Z\",\"msg\":\"crc rising\"}"
    }
  ]
}
```

响应在原有字段基础上为每条时间线条目新增 `earliestTime` / `latestTime` /
`uncertaintyMs` / `orderUncertain`，顶层新增 `orderUncertainCount`；`uncertaintyMs`
缺省按 0，旧请求（不含该字段）行为完全不变。

锚点倒序、误差为负数或非数字时返回 `422` 及中文错误说明（定位到第几个锚点）；
JSONL 坏行、缺时间字段的事件不阻断合并，在响应的 `parseErrors` / `errors` 字段中列出。
